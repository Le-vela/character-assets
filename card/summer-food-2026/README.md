# Food MaAM 여름 음식 카드 제작 준비안

첨부된 김치찌개 카드는 시각적 레퍼런스로만 사용한다. 이미지 안의 문구나 수치는 신규 카드의 사실 정보로 복사하지 않는다.

## 범위

- 기존 카드: 20종 (`001`–`020`)
- 중복 제외: 냉면 (`008_nmy`)
- 신규 카드: 20종 (`021`–`040`)
- 구성: 차가운 면 6종, 시원한 별미 8종, 보양식 4종, 디저트 2종
- `021`–`040`은 캐릭터 없이 Local Fine Dining 카드로 제작한다.

초계국수는 닭육수와 겨자 풍미가 중심인 여름 별미로 분류했다. 냉짬뽕 추가 후 신규 20종은 `6 + 8 + 4 + 2`로 구성된다.

## 제작 원칙

1. 파일명은 `{id}_{code}.png` 형식을 사용한다.
2. 카드 비율, 좌우 2면 구성, 크림색 바탕, 짙은 청록 포인트는 기존 LM 카드 체계를 따른다.
3. 음식 사진 영역과 캐릭터 영역은 별도 원본으로 준비한 뒤 카드 레이아웃에서 합성한다.
4. 음식명, 영문명, 설명, 영양 수치, 가격, 조리 시간은 생성 이미지에 직접 맡기지 않고 코드로 조판한다.
5. 영양 수치와 알레르기 정보는 검증 전까지 확정값으로 표시하지 않는다.
6. 로고와 기존 MaAM 캐릭터 자산은 저장소의 원본을 재사용하며 새 로고를 생성하지 않는다.
7. 이미지 생성물에는 글자, 로고, 워터마크가 들어가지 않게 한다.

## 이미지 생성 공통 프롬프트 골격

```text
Use case: product-mockup
Asset type: Food MaAM card food hero source
Primary request: [manifest의 hero]
Scene/backdrop: 한국 음식 전문점의 정갈한 테이블, 카드 합성을 위한 단순한 배경
Style/medium: 고급 상업 음식 사진, 사실적인 재료와 질감
Composition/framing: 세로 카드용 근접 촬영, 주 음식이 중앙에 크고 명확하게 보이도록 구성
Lighting/mood: 부드러운 자연광, 청량하고 식욕을 돋우는 여름 분위기
Constraints: 음식의 전형적인 형태와 고명을 정확히 표현, 카드 크롭을 위한 충분한 여백
Avoid: 글자, 로고, 워터마크, 사람 손, 과도한 소품, 잘못된 재료
```

캐릭터 소스는 `manifest.json`의 `character_prop`을 음식별 소품으로 사용하되, 기존 MaAM 로봇의 얼굴·몸체·색상 체계를 보존한다.

## 작업 순서

1. `manifest.json`의 이름, 코드, 분류를 확정한다.
2. 음식별 hero 원본을 생성하고 음식 고증을 확인한다.
3. 기존 MaAM 로봇을 기반으로 음식별 소품 버전을 만든다.
4. 텍스트·수치 데이터를 별도 구조화 파일에 작성하고 검수한다.
5. 기존 LM 카드 템플릿으로 19장을 조판한다.
6. 축소판 접촉 시트로 전체 통일성과 중복 구도를 확인한다.
7. 개별 원본 크기에서 한글, 영문명, 잘림, 색 대비를 최종 검수한다.

## 상태값

- `planned`: 제작 대기
- `hero_ready`: 음식 원본 완료
- `character_ready`: 캐릭터 원본 완료
- `composed`: 카드 조판 완료
- `verified`: 최종 검수 완료
